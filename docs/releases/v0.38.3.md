# MoleKey 0.38.3 — Finder stability and F12 recovery

Released on GitHub on 2026-10-27.

## English

- **Multi-monitor Finder startup:** position navigation windows on the Visual
  Studio monitor while still hidden, addressing a brief empty frame on the
  primary monitor. Fit oversized saved windows to the current work area and DPI.
- **Responsive file loading:** collect the File Finder list in small batches,
  allowing painting and input between batches. Closing or restarting with F5
  cancels the previous scan. Refreshes preserve the current selection and preview.
- **Scrolling and path display:** give result lists an explicit scrolling
  viewport and vertical scrollbar. Measure full paths independently from their
  shortened display text so repeated layout does not change the measurement basis.
- **F12 recovery:** repair a missing Go to Definition binding once per Visual
  Studio instance, even if the shortcut profile is already marked as applied.
  The repair requires a backed-up F12 and an existing Alt+G assignment. It keeps
  current shortcuts and does not take Global F12 from another command.

Compatibility remains Visual Studio 2022 / 2026, x64 and ARM64, .NET Framework 4.8.
The package identity and publisher remain unchanged for upgrades.

## 한국어

- **다중 모니터 Finder 표시 개선:** 창을 숨긴 상태에서 VS가 있는 모니터에
  먼저 배치합니다. 저장된 창이 너무 크면 현재 모니터의 작업 영역과 배율에
  맞춰 줄입니다.
- **파일 목록 수집 응답성 개선:** 수집을 나눠 처리해 화면 갱신과 입력에
  제어권을 돌려줍니다. 창 닫기 또는 F5 재실행 시 이전 수집을 취소하며,
  새로고침 후 선택 항목과 미리보기 위치를 유지합니다.
- **스크롤·경로 표시 안정화:** 결과 목록에 스크롤 영역과 세로 스크롤바를
  명시적으로 구성하고, 경로의 원본 폭과 줄임 표시를 분리합니다.
- **F12 복구:** 원래 백업에 F12가 있고 현재 Alt+G만 남아 있는 경우,
  ‘정의로 이동’의 F12 연결을 VS 인스턴스별로 한 번 복구합니다.
  기존 키와 다른 명령의 전역 F12 배정은 유지합니다.

지원 환경은 기존과 동일하게 Visual Studio 2022 / 2026, x64·ARM64,
.NET Framework 4.8입니다. 기존 설치를 업데이트할 수 있도록 패키지 ID와
게시자 정보는 유지했습니다.

## Validation and limits

- The user confirmed the Finder fixes after testing. The reported F12 issue
  was diagnosed in running VS: Alt+G was assigned, F12 was absent. Adding F12
  was verified by reading the live bindings back.
- Automated coverage includes hidden-window placement, monitor size limits,
  cancellable collection, actual list templates, scrolling, path measurement,
  and F12 repair decisions. Final package checks are recorded separately.
- An individual slow VS project-system or filesystem call can still block
  until that call returns. Other synchronous file-list consumers are unchanged.
- On a display smaller than the designed minimum, the frame remains reachable;
  some content can still be clipped. A complete installation/upgrade and
  cross-version/architecture/DPI test matrix has not been completed.
